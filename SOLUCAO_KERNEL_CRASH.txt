# 🆘 KERNEL CRASH CÉLULA 2 — RESOLVIDO ✅

## O Problema

A célula 2 do NN_02_DNN_Correlator_GPU.ipynb estava **crashando o kernel** com o erro:
```
The Kernel crashed while executing code in the current cell
```

**Causa**: O kernel Linux estava matando o processo Python por **Out of Memory (OOM)**

```
oom-kill: Killed process (python) — anon-rss:6860392kB (6.9 GB)
```

### Por quê aconteceu?

A célula 2 tentava carregar **3 datasets gigantes** todo na memória de uma vez:
- `train/z_eq`: 280k × 1024 = 1.1 GB
- `val/z_eq`: 35k × 1024 = 0.14 GB  
- `test/z_eq`: 35k × 1024 = 0.14 GB
- **Total**: ~1.5 GB de dados + overhead NumPy/TensorFlow = 6-7 GB
- **Disponível**: ~5 GB em WSL
- **Resultado**: ❌ OOM kill!

---

## A Solução

Troquei a abordagem de **"carregar tudo de uma vez"** para **"carregar sob demanda"** (lazy loading):

### ✅ O que foi corrigido

#### Célula 2 — Load Dataset
Agora usa `tf.data.Dataset.from_generator()` que lê dados em chunks:

```python
def load_h5_generator(h5_path, split, chunk_size=2000):
    """Lê HDF5 em pedaços de 2000 amostras."""
    with h5py.File(str(h5_path), 'r') as f:
        z_data = f[f'{split}/z_eq']
        y_data = f[f'{split}/y']
        # Lê 2000 amostras por vez (8 MB cada)
        for start_idx in range(0, len(z_data), chunk_size):
            end_idx = min(start_idx + chunk_size, len(z_data))
            z_chunk = z_data[start_idx:end_idx].astype(np.float32)
            y_chunk = y_data[start_idx:end_idx].astype(np.float32)
            # Yield (z, y) uma amostra por vez
            for i in range(len(z_chunk)):
                yield z_chunk[i], y_chunk[i]
```

#### Célula 3 — tf.data Pipeline  
Prepara o dataset com batching + prefetch:

```python
train_ds = train_gen_ds.shuffle(10000).batch(128).prefetch(tf.data.AUTOTUNE)
```

## ❓ FAQ

**P: Por que não carregar tudo de uma vez?**  
R: A máquina não tem RAM suficiente. Lazy loading lê apenas o necessário.

**P: Vai ficar mais lento?**  
R: Um pouco na primeira época, mas GPU fica sempre ocupada. Aceitável.

**P: Posso aumentar batch size?**  
R: Não recomendado. Tente apenas se tiver muita RAM disponível.

**P: E se ainda crashear?**  
R: Reduza BATCH_SIZE para 64 em Célula 3 e verifique dmesg.
